Guide de bonnes pratiques

La console est un outil de diagnostic : les messages doivent être utiles sans exposer de données sensibles ni produire de bruit inutile.

Choisir le bon niveau

  • debug pour les détails de diagnostic pendant le développement.
  • log et info pour le suivi du fonctionnement normal.
  • warn pour une situation dégradée, et error pour un échec.

Rendre les messages utiles

  • Décrivez l'événement et son contexte, par exemple avec un identifiant non sensible.
  • Utilisez table, dir et group pour organiser les données.
  • Nommez les compteurs et chronomètres afin d'éviter les collisions.

Préserver la confidentialité et les performances

  • Ne journalisez jamais de mot de passe, jeton, cookie ou donnée personnelle.
  • Évitez les grands objets et les messages dans des boucles fréquentes.
  • Limitez les messages de diagnostic à l'environnement de développement.
